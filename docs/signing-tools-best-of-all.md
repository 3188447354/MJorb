# 怎么「集齐各类签名的优点」

- 建立：2026-09-19
- 前置阅读：`docs/signing-tools-comparison.md`（各工具流程拆解 ✓）

---

## 一、先泼一盆冷水：**有些优点是互斥的，不可能全要** ✗

「集齐所有优点」这句话，**正确读法是**：
> **把「不互斥的优点」全部要满 ✓；互斥的必须选一边 ✗；代价太大的不能要 ✗✗。**

### 三组**互斥**（选了 A 就没有 B）

| A | B | 为什么互斥 |
|---|---|---|
| **自己的证书**（不掉签 ✓） | **卖家的共享证书**（不用 Apple ID ✓） | 共享证书的**代价就是**会集体掉签 ✗ —— 两者是同一个东西的两面 |
| **手机端**（不用电脑 ✓） | **电脑端**（大包快、支持旧系统 ✓） | 手机的内存 / CPU / 后台限制决定了它比电脑慢 ✗ |
| **真签名**（走 Apple 正规流程 ✓） | **TrollStore**（永久不掉 ✓） | TrollStore **根本不签名** ✗ —— 靠系统漏洞绕过校验 |

### 三条**不能碰的红线** ✗✗

| 红线 | 为什么不能碰 |
|---|---|
| **共享/企业证书** | ① 卖家证书被吊销 ⇒ **所有用户集体掉签** ✗；② **违反 Apple 开发者协议** ✓ |
| **TrollStore 式绕过** | 依赖**系统漏洞** ✗，系统一升级就失效 ✓，且属于绕过安全机制 ✓ |
| **滥用企业证书** | Apple 明令禁止 ✗，且必然被吊销 ✓ |

## 三、按「性价比」排序的行动清单

| 优先 | 做什么 | 收益 | 代价 |
|---|---|---|---|
| **P0** | **测掉节流**（第 9 条 ✓） | Apple 阶段从「20+ 次串行」变成并发 ⇒ **快数倍** ✓ | 一次真机测试 ✓ |
| **P1** | **证书健康检查**（第 10 条 ✓） | 签名前就知道证书会不会被吊销 ⇒ **少一次失败** ✓ | 一次 OCSP 请求 ✓ |
| **P2** | **补齐 zsign 的实用开关**（第 13/14 条 ✓） | 「去扩展 / 改版本号 / 导出图标」这些高级用法 ✓ | 中等 ✓ |
| **P3** | **UI 打磨**（第 12 条 ✓） | 体感 ✓ | 大 ✓ |
| **P4** | **电脑端辅助**（第 11 条 ✓） | 超大包（抖音 780MB）在电脑上签更快 ✓ | **会动摇「不用电脑」的定位** ✗，需谨慎 ✓ |

## 四、一句话

> **Seal 的正确路线不是「变成全能工具」✗，而是**在自己定位内做到最好**✓：
> 保住「自己的证书 + 手机端」这两个根本 ✓，
> 把**速度（并发）、缓存（已有）、诊断（已有）、自动续签（已有）**要满 ✓，
> 再补上**证书健康检查**和**实用开关** ✓。
>
> **共享证书和 TrollStore 那两条路，看着省事，但代价是**集体掉签 / 系统漏洞**✗ ——
> 那不是「优点」，是**别人的成本**✓。**
