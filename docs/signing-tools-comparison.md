## 一、先说结论：**签名工具之间的差别，90% 不在「签名」**

**所有工具最终都要做同一套 Mach-O 签名** ✓ —— 因为 **Apple 的校验规则是固定的** ✓：

```
CodeDirectory（把代码按页做哈希） → CMS 签名（用你的证书签它） → 塞进 __LINKEDIT
```

**⇒ 这一步谁做都一样** ✓（zsign / ldid / codesign / rork-sign ✓，算法必须一致 ✓）

**⇒ 真正的差别在这四件事上** ✓✓：

| # | 差别 | 决定了什么 |
|---|---|---|
| **1** | **证书从哪来** | **自己的账号** ✓ vs **卖家共享** ✗ —— **这是最大的分野** |
| **2** | **设备身份（anisette）从哪来** | 本地生成 vs 服务端 ✓ |
| **3** | **描述文件（profile）怎么拿** | 要 Apple 门户交互 ✓ vs 直接给现成的 ✓ |
| **4** | **在哪跑** | 手机端 vs 电脑端 ✓ |

## 二、完整流程（**9 步**，每步在干嘛）

> 前 4 步是「**拿资格**」，后 5 步是「**干活**」✓ —— 各工具差别全在前 4 步 ✓

### 🔑 拿资格阶段（要和 Apple 打交道）

| 步 | 干什么 | 为什么必须做 | 各家差异 |
|---|---|---|---|
| **1** | **取设备身份（anisette）** | Apple 要确认「是这台设备在操作」✓ 包含 `machineID` + **一次性码** ✓ | **Seal/SideStore**：本地生成 ✓（`AnisetteKit`）<br>**Sideloadly**：电脑上跑 anisette 服务 ✓<br>**共享证书类**：**服务端生成** ✓ **[推断]** |
| **2** | **拿证书（.p12）** | 证明「你有资格签」✓ | **自签类**：用**你自己的 Apple ID** 去门户创建（免费账号 7 天 / 只有 1 张）✓<br>**共享证书类**：**卖家给你一张**（企业证书 / 批量个人证书）✗ |
| **3** | **建 App ID** | Apple 要求「每个 Bundle ID 必须注册」✓ | **自签类**：每次签名自动注册 ✓（免费账号 10 个/7 天）<br>**共享证书类**：**用通配符 ID** 或卖家的现成 ID ✓ |
| **4** | **取描述文件（.mobileprovision）** | 它把「证书 + App ID + 设备 UDID」绑在一起 ✓ | **自签类**：必须**带上你的 UDID** 去门户申请 ✓<br>**共享证书类**：**用卖家的超级描述文件**（含大量 UDID）✗ |

### 🔧 干活阶段（**这一步所有工具几乎一样** ✓）

| 步 | 干什么 | 细节（以 zsign / rork-sign 为准 ✓） |
|---|---|---|
| **5** | **解包 IPA** | 解出 `Payload/App.app/` ✓ |
| **6** | **改 Bundle** | 改 `Info.plist`（Bundle ID / 名称 / 版本 ✓）；**替换 `embedded.mobileprovision`** ✓；**注入 dylib**（改 `LC_LOAD_DYLIB` ✓）—— zsign 的 `-b/-n/-l/-P` 就是干这个 ✓ **[源码]** |
| **7** | **写 entitlements** | 从**描述文件里派生** ✓（免费账号的 entitlement 很有限 ✓）—— 这一步错了会导致**装完启动就崩** ✗ |
| **8** | **自内向外逐个签 Mach-O** | `Frameworks/ → PlugIns/*.appex → 主 App` ✓<br>每个二进制：改 load commands → **算 CodeDirectory 页哈希** → **CMS 签名** ✓<br>**再 seal 资源**（`_CodeSignature/CodeResources` ✓）<br>zsign 有 `.zsign_cache` ✓、rork-sign 有 `BundleSignatureCache` ✓（跳过没变的 ✓） |
| **9** | **重打包 + 安装** | 压回 IPA ✓ → 通过 `installd` / `ideviceinstaller` 装上 ✓ |

## 四、为什么「共享证书」类工具会**集体掉签**

**它们的流程** ✓ **[推断]**：

```
卖家买一张（或几张）企业/个人证书
  → 把它放在服务器上
  → 所有用户签名时都用这一张
  → Apple 发现「一张证书签了几万个 App、遍布全球」
  → 吊销这张证书 ✗
  → 所有用它签过的 App 全部打不开 ✗✗
```

**⇒ 这就是「掉签」的本质** ✓ —— **不是工具坏了，是那张证书被 Apple 吊销了** ✗

**⇒ 而自签类（Seal / SideStore / Sideloadly）不会集体掉签** ✓ ——
**每个人的证书都是自己的** ✓，最多是**自己 7 天到期** ✓（续签即可 ✓）

## 五、Seal 在这张图里的位置

```
第 1 步 设备身份  →  本地生成（AnisetteKit + 本地 Unicorn 模拟）✓   ← 今天修的 1100 就在这
第 2 步 证书      →  自己的 Apple ID，免费账号只有 1 张 ✓
第 3 步 App ID    →  自动注册（主 App 优先 ✓）
第 4 步 描述文件  →  自己申请（带本机 UDID ✓）
第 5~9 步 重签    →  rork-sign（zsign 兼容 ✓）+ 4 个 Seal 补丁 ✓
```

**⇒ 全部在手机上完成** ✓ —— 这是 Seal 与 Sideloadly 的核心差别（**不需要电脑** ✓），
也是它与 SideStore 相同、与「共享证书类」根本不同的地方 ✓

## 六、一句话总结

> **「签名」这一步是死的（Apple 规定的）✓；
> 各家工具的差别，全在「证书从哪来、设备身份谁造、描述文件谁给」✓。
> 自签类靠自己的账号（安全但要续签 ✓）；共享证书类靠卖家的证书（省事但会集体掉签 ✗）；
> TrollStore 干脆不签名（靠漏洞 ✓）。**
