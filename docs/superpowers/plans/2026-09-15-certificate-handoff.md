# 外部签名 Seal 首次续签 Implementation Plan

> 按 subagent-driven-development 执行独立启动确认子任务，其余证书链由主任务执行；用户已批准修复并推送到 sunuannian1/Trae-seal，全部完成后跟进云 CI。

**Goal:** 爱思安装的 Seal 在没有本机私钥时保留当前运行证书，尝试建立本机签名身份；失败准确说明原因；覆盖安装后重启核验本机签名能力。

**Architecture:** 复用现有 AltSign 创建、保存与安装链。抽取证书复用/错误策略为可测试函数；自动清理只针对已核验无引用的无私钥证书。启动确认只读运行包并核对持久化私钥，不自动撤销旧证。

**Tech Stack:** Swift / Swift Testing / AltSign（固定 revision）/ Windows 静态守卫 / macOS GitHub Actions。

## 自查与边界

1. 验收：请求无效不会触发撤销；外部证书无私钥时不能谎称本机有私钥；新身份持久化后再安装；重启才能确认接管。
2. 覆盖：当前与历史 P12、序列号前导零、证书有效期不足/解析失败、无设备清单、无运行包证书、创建超时、安装失败与系统杀进程。
3. 回退：旧 Seal 证书始终保留；没有名额时明确电脑辅助恢复，不重复清理重试；保留旧 P12。
4. 规范：零 Rust 改动；唯一错误码；日志不包含账号/凭据；主 target 与扩展版本一致。
5. 上游：AltSign 将本地 CSR 失败及 3250 映射 invalidCertificateRequest，7460 映射 tooManyCertificates。直接对齐，不自行把请求无效解释为名额满。
