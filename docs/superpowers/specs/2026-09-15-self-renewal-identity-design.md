# Seal 1.0 自续签身份与单次替换设计

## 目标

Seal 首次由第三方电脑签名工具安装到 iPhone 或 iPad。Seal 不导入电脑端 P12，也不假设自己拥有电脑证书的私钥。在当前 Seal 仍可运行的前提下，Seal 创建并保存本机可控的签名身份，完成一次覆盖安装，将自身从外部电脑身份安全接管为本机身份；之后重复使用该本机证书完成日常续签。

本设计解决第一批发布阻断问题：

1. 准确识别设备上实际运行的 Seal 及其扩展由谁签名。
2. 统一外部身份、本机身份、候选身份和已安装身份的定义。
3. 把自续签改成只提交一次安装、跨进程确认结果的事务。
4. 保证失败时不提前撤销当前签名证书，不误删可恢复资料。

## 1.0 范围

本批次包含：

- 读取 Seal 主程序及所有扩展的实际代码签名身份。
- 读取并核对 Team ID、Bundle ID、描述文件 UUID、到期时间和授权证书集合。
- 判断本机是否持有某张证书对应的私钥。
- 建立统一身份模型和自替换状态机。
- 创建 Seal 本机证书 B 并保存私钥。
- 用 B 签名候选 Seal，向设备提交一次覆盖安装。
- 由覆盖后的新进程确认安装结果并结算事务。
- 精准清理本次事务产生的临时资料和已确认过时的描述文件。
- 无法自动恢复时进入电脑覆盖恢复状态。

本批次不包含：

- 从电脑导入 P12。
- Recovery 双 App。
- 云签名或服务器保存 Apple ID。
- 证书导出能力调整。
- 承诺后台一定能在过期前执行。
- 多 App 自动续签改造。
- 为释放槽位自动撤销无法确认影响范围的证书。

## 核心原则

### 现实状态优先

数据库记录、历史交接记录和描述文件只能作为线索。Seal 的当前身份必须以设备上实际安装包的代码签名为准。记录与现实冲突时，更新记录，不让现实迁就旧记录。

### 授权证书不等于实际签名证书

描述文件可能授权多张证书。不得使用 `DeveloperCertificates.first` 或证书序列号数组第一项推断真实签名者。必须解析主 Mach-O 和每个扩展 Mach-O 的代码签名，得到实际叶子证书指纹，再与描述文件和 Apple 账户证书核对。

### 当前可运行身份不可提前破坏

本机身份 B 被新进程确认前，不撤销当前 Seal 的实际签名证书 A，不删除维持当前 Seal 运行所需的描述文件，不把候选签名成功当成接管成功。

### 一次提交，跨进程确认

一次自替换事务最多向安装通道提交一次安装。旧进程负责准备和提交；覆盖后的新进程负责确认和结算。旧进程不等待自身被替换后继续执行成功逻辑。

## 统一领域模型

### InstalledIdentity

代表设备上当前实际运行的 Seal：

- 主 App 的 Bundle ID、Team ID、代码签名证书 SHA-256 指纹。
- 所有扩展各自的 Bundle ID、Team ID、签名证书指纹。
- 当前嵌入描述文件 UUID、到期时间和授权证书指纹集合。
- App 版本、构建版本。
- 本次读取时间和读取完整性。

读取不完整时返回“无法确认”及原因，不伪装成不存在或无关联。

### LocalSigningIdentity

代表 Seal 本机真正能够用于签名的身份：

- Apple 账户标识和 Team ID。
- 证书指纹、序列号和有效期。
- Keychain 私钥引用。
- 本地可签名验证结果。
- Apple Portal 中的证书状态。

只有证书、私钥匹配且完成一次本地签名验证，才是可用身份。

### CandidateIdentity

代表准备覆盖安装的候选 Seal：

- 目标 Bundle ID、Team ID和版本。
- 目标主 App 与扩展身份。
- 使用的 LocalSigningIdentity。
- 新描述文件 UUID 和到期时间。
- 候选 IPA 的受保护文件引用和摘要。
- 完整签名验证结果。

CandidateIdentity 永远不能覆盖 InstalledIdentity；两者必须同时保存并明确区分。

### SelfReplacementTransaction

代表一次不可重复提交的自替换事务：

- 全局唯一 transactionID。
- 创建时间和最后更新时间。
- 开始时的 InstalledIdentity 快照。
- CandidateIdentity。
- 当前状态。
- installSubmissionID 和是否已提交。
- 每一步的结果、错误分类和可重试性。
- 本事务创建的文件、描述文件和记录清单。

事务记录必须在安装提交前持久化，并采用原子写入。

## 产品状态机

Seal 对用户展示以下稳定状态：

1. `externalBootstrap`：当前 Seal 由外部电脑身份签名，本机尚无可用身份。
2. `preparingLocalIdentity`：正在检查槽位、创建或验证本机身份 B。
3. `localIdentityReady`：B 可用于签名，但当前运行的 Seal 仍未确认使用 B。
4. `awaitingReplacementConfirmation`：安装已经提交，等待新进程核对现实状态。
5. `selfManaged`：当前 Seal 主程序和所有扩展均已确认使用 B。
6. `recoveryRequired`：无法安全判断或自动继续，需要电脑覆盖恢复。

状态迁移规则：

- `externalBootstrap → preparingLocalIdentity`：环境、账户和设备通道满足要求，用户开始接管。
- `preparingLocalIdentity → localIdentityReady`：B 的证书与私钥已保存，并通过本地签名验证。
- `localIdentityReady → awaitingReplacementConfirmation`：候选 IPA 验证通过，事务已落盘，安装提交成功返回。
- `awaitingReplacementConfirmation → selfManaged`：新进程读取到的 InstalledIdentity 与 CandidateIdentity 完整匹配。
- 任一准备阶段失败：保留当前 InstalledIdentity，回到可重试状态。
- 已提交后无法确认：不得再次自动提交；先对账，仍不明确则进入 `recoveryRequired`。
- `selfManaged → localIdentityReady`：日常续签候选已经准备好，随后复用同一替换事务。

## 证书槽位处理

### 存在空槽位

保留当前外部证书 A，创建本机证书 B。创建失败不改变 A，不改变当前 Seal。

### 两个槽位均被占用

1. 从 InstalledIdentity 确认当前实际签名证书 A。
2. A 永久排除在本次可撤销集合之外。
3. 对其他证书 C 汇总当前设备已安装 App 的实际关联。
4. 明确告知当前关联只覆盖本机，其他设备影响可能无法确认。
5. 只有用户确认后才撤销 C。
6. 撤销 C 后创建 B；如果创建失败，A 仍保持有效。

若无法确定 A、无法找到候选 C，或用户不同意影响范围，则停止自动接管并给出电脑处理入口。

## 自替换事务

### Prepare

1. 刷新 InstalledIdentity。
2. 验证当前状态允许开始新事务。
3. 验证 LocalSigningIdentity B 的证书、私钥和 Portal 状态。
4. 获取新的主 App 与扩展描述文件。
5. 使用当前 Seal 的确切 Bundle ID 体系签名候选包。
6. 离线验证候选包所有可执行文件、权限、描述文件和签名链。
7. 写入 CandidateIdentity 与事务记录。

Prepare 失败可以安全重试，不改变已安装 Seal。

### Submit Once

1. 在调用安装通道前，原子写入“准备提交”。
2. 获取并持久化 installSubmissionID。
3. 向安装通道提交一次候选 IPA。
4. 一旦调用已经发出，无论旧进程收到成功、超时还是连接中断，都标记为“可能已提交”。
5. 禁止同一 transactionID 再次调用安装。

旧进程不得通过循环重试第二次安装，也不得在返回后宣布接管完成。

### Reconcile At Next Launch

每次 Seal 启动首先进行只读对账：

1. 读取未结算事务。
2. 重新构建 InstalledIdentity。
3. 比较实际 Bundle ID、Team ID、主程序及扩展证书指纹、描述文件 UUID 和目标版本。
4. 完整匹配 CandidateIdentity：确认是新进程，进入结算。
5. 仍匹配旧 InstalledIdentity：安装没有生效；允许用户创建新事务重试，但不复用旧 transactionID。
6. 部分匹配或读取失败：显示无法确认，禁止自动安装，进入人工检查或电脑恢复。

### Settle

确认成功后：

1. 将本机身份 B 标为 Seal 当前签名身份。
2. 更新新的到期时间和描述文件记录。
3. 删除本事务候选 IPA、临时解包目录和交接记录。
4. 删除已确认不再被当前安装使用的旧 Seal 描述文件。
5. 结束事务并保留必要的审计摘要。

结算不自动撤销外部证书 A。证书撤销属于独立、需要影响确认的操作。

## 日常续签

进入 `selfManaged` 后，日常续签重复使用本机身份 B：

1. 检查 B 的有效性和私钥可用性。
2. Apple 会话有效则获取新描述文件；会话失效则只要求重新认证。
3. 使用 B 签名相同版本或已验证的新版本 Seal。
4. 执行新的 SelfReplacementTransaction。
5. 新进程确认后更新到期时间。

七天描述文件更新不创建新开发证书，也不撤销 B。版本更新和签名续期使用同一替换机制，但必须作为不同用户意图记录。

## 错误与恢复

错误至少分为：

- 可直接重试：临时网络、Apple 服务暂时不可用、设备通道断开。
- 需要用户操作：Apple 重新认证、开启 VPN、重新配对、开启开发者模式。
- 需要释放证书槽位：展示保护对象和候选撤销对象后由用户确认。
- 当前版本仍安全：Prepare 或签名验证失败，保持现有 Seal 不变。
- 已提交待对账：不允许再次安装，等待下次启动读取现实状态。
- 需要电脑恢复：实际身份部分匹配、当前身份无法读取、覆盖后不能建立安全状态。

电脑恢复固定要求：不卸载 Seal，使用与设备当前安装一致的 Bundle ID、扩展 Bundle ID 和应用标识体系覆盖安装；电脑工具应使用原 Apple ID 对应的同一 Team。若无法保持同一 Team 或应用标识前缀，Seal 必须提前说明系统可能拒绝覆盖或无法保留原容器数据，不能承诺无损恢复。恢复启动后废弃未完成事务的执行权，仅保留审计信息，重新读取 InstalledIdentity 并从 `externalBootstrap` 开始判断。

## 数据与清理边界

- Apple 凭据、证书私钥和事务记录继续使用本机受保护存储。
- 临时 IPA 和解包目录必须归属于明确 transactionID。
- 清理函数只接收事务生成的显式资源清单，不接受 Bundle ID 通配删除。
- 描述文件删除前再次读取当前 InstalledIdentity，当前使用的 UUID 永远不能删除。
- 证书删除与描述文件清理分离；结算成功不等于允许撤销旧证书。
- 关键持久化失败必须阻止下一步，不能以静默 `try?` 忽略。

## UI 行为

本批次只要求支持闭环所需的界面状态：

- 当前 Seal：外部电脑签名、本机接管中、本机管理、等待确认或需要恢复。
- 当前真实签名证书 A 与准备使用的本机证书 B 分开显示。
- 已提交安装后按钮变为“检查安装结果”，不能再次显示“立即安装”。
- 错误信息同时说明发生了什么、当前 Seal 是否仍安全、用户下一步做什么。
- 证书关联明确标注“只统计本机已安装 App”；未知信息显示“无法确认”。

## 验收标准

以下场景全部通过，第一批才算完成：

1. 电脑证书 A 安装的 Seal 能在空槽位创建 B 并成功接管。
2. 两槽已满时绝不撤销 A；用户确认撤销非 A 证书后能创建 B。
3. B 创建失败、签名失败或候选验证失败时，原 Seal 继续运行。
4. 安装 API 返回超时、断连或进程被终止时，同一事务不会第二次提交。
5. 新 Seal 启动后能凭真实代码签名确认接管，而非凭数据库自报成功。
6. 主 App 或任一扩展身份不匹配时，不得进入 `selfManaged`。
7. 连续完成至少两轮日常续签，第二轮复用 B，不创建新证书。
8. 成功结算只删除旧描述文件和本事务临时资料，不撤销 A 或 B。
9. 失败事务经过重启可以对账；无法确认时稳定进入电脑恢复，不自动循环安装。
10. 电脑使用相同 Bundle ID、扩展标识和 Team 覆盖恢复后，Seal 数据保留并能重新识别为外部启动状态。
11. 上述主流程分别在受支持的 iPhone 和 iPad 真机完成。

## 实施边界

实现时优先复用现有签名、Apple Portal、Minimuxer、Keychain 和配对模块，只替换它们之上的身份判断与自替换编排。第一批不借机重构无关页面或普通 IPA 管理功能。所有旧的重复安装、启动自动补装和基于描述文件首张证书推断身份的入口，必须在新路径启用时被移除或封死。
