## 一句话总览

> **两边的「主干」一样**（都是：取设备身份 → 拿证书 → 建 App ID → 取描述文件 → 重签 → 装机），
> **差别全在细节**：
> - **Seal 多了**：自动重试、诊断日志、守卫、对失败的分级处理；
> - **Seal 少了**：并发、蜂窝批量、图形界面的一些打磨；
> - **Seal 错过的**：**上游「每次请求前换一份新设备身份」的用法** ✗（今天最大的 bug 就是这个 ✓）。

## 三、结论（三句话）

1. **主干流程两边一样** ✓ —— 所以上游的**做法**值得跟（今天已跟了 2 条 ✓）；
2. **Seal 多出来的东西分两类** ✗✓：
   - **「更严格」**（白撤证书 / 过度限速）⇒ **该去掉** ✓
   - **「更完整」**（自动重试 / 诊断 / 守卫）⇒ **该保留** ✓
3. 🔄 **签名内核现在**能逐字对照**了** ✓ —— `Vendor/CodeSignKit` 与上游 `diff -r -w`
   **只差 `Package.swift` 一行**（`swift-crypto` 4.3.1 → 4.5.2 ✓），
   `Vendor/SideSign` 则删掉了 anisette / 门户两层（Seal 用自己的 ✓）。
   ⇒ 旧的 `docs/upstream/rork-sign-0.6.5-vs-Vendor.diff` 只作**历史记录** ✓
   （`Vendor/rork-sign` 已删除 ✗）。
